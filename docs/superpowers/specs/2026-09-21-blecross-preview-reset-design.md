# BLE Cross 公式预览自动复位设计

## 背景

BLE Cross 的公式预览当前直接从 3D 魔方的现有画面和预览游标继续执行。连续点击播放、切换 XCross 槽位，或在预览前改变 3D 状态后，公式可能作用在残留状态上，导致画面与公式不一致。

当前求解结果已经绑定求解时的视角快照 `bestViewOps`，但没有同时保留求解器输入的核心状态，因此不能仅靠现有 `resetRound()` 精确恢复公式起点。`resetRound()` 恢复的是本轮训练起点，还会改动计时、步数和训练阶段；模式或视角重算后的公式不一定对应这个旧起点。

## 目标

- 每次点击 `▶` 前恢复该批求解结果对应的 3D 起始画面，并从公式第 1 步开始完整播放。
- 单步 `⏭` 在游标为 0、即将执行第 1 步时，先恢复同一起始画面，再执行第 1 步。
- 单步 `⏮` 继续按当前游标回退；回退到 0 后画面自然处于公式起点。
- Cross 与 XCross 四个槽位遵守相同行为。
- 预览复位只影响 3D 预览画面和预览游标，不改变训练计时、训练步数、用户公式、蓝牙权威状态或当前阶段。

## 非目标

- 不改变“重置”按钮的现有训练语义。
- 不改变求解算法、公式换面逻辑或 FR/FL/BR/BL 槽位映射。
- 不改变 `⏮` 的逐步回退行为。
- 不新增界面控件。

## 设计

### 求解快照

每次 `requestBest` 发起求解时，复制并绑定两部分数据：

1. 求解器接收的 54 字符核心状态。
2. 同一次请求的视角链快照。

只有当前请求成功返回时，才把两者一起发布为当前最优解预览快照。异步过期结果不得覆盖新请求的状态或视角。Cross 与同批 XCross 四槽位共享这一份快照。

### 恢复公式起点

新增一个仅用于公式预览的内部恢复操作：

1. 结束尚未落定的 3D 动画。
2. 用求解核心状态重建贴纸状态。
3. 依次即时应用求解时的视角链，恢复公式展示所在的屏幕坐标系。
4. 清零目标公式的预览游标；完整播放时清理全部公式游标，避免切换 XCross 槽位继承残留进度。
5. 保持预览保护开启，避免恢复过程触发手动模式的判定、计步或状态重算。

恢复操作不调用 `resetRound()`，也不修改 `predicted`、`moveCount`、计时字段或训练阶段。

### 按钮行为

- `playBest(formula)`：校验公式与快照有效后，始终恢复公式起点，将游标设为 0，然后把完整公式送入现有播放队列。
- `stepBest(formula, +1)`：游标为 0 时先恢复公式起点，再把第一步送入播放队列；游标大于 0 时沿用当前画面继续下一步。
- `stepBest(formula, -1)`：保持现有逻辑，对上一条记号取逆并回退游标。
- GIF 自动播放继续调用 `playBest`，即使调用前已有一次训练重置，也以求解快照再次复位，保证录制起始帧正确。

快照无效或公式为空时沿用现有防御行为：不启动播放，不修改训练状态。

## 测试

扩展 BLE Cross 浏览器回归脚本，至少覆盖：

1. Cross：先执行一段预览或主动污染 3D 画面，再次点击 `▶`，最终状态必须等价于“求解快照 + 完整公式”，且游标从 0 走到总步数。
2. Cross 首步：污染 3D 画面且游标为 0，点击 `⏭` 后状态必须等价于“求解快照 + 第一步”。
3. XCross：播放一个槽位后改播另一个槽位，第二次播放必须从共享求解快照开始，不能叠加前一个槽位的结果。
4. `⏮`：执行首个 `⏭` 后回退，状态回到求解快照且游标为 0。
5. 现有模式切换、y/y′/z2 重算和蓝牙多轮重置回归继续通过。

## 验收标准

- 任意 `▶` 点击均从该公式的求解快照第 1 步开始。
- 首个 `⏭` 执行前必定恢复求解快照。
- Cross/XCross、标准视角及 y/y′/z2 后的展示帧均正确。
- 预览不会改变训练计数或蓝牙权威状态。
- `npm run test:ble`、`npm run verify:blecross` 与生产构建通过。
