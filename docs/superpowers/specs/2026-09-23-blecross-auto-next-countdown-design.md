# BLE Cross 自动下轮倒计时设计

## 背景

训练成功且开启「自动下轮」后，页面会等待 2.5 秒再开始下一轮，但等待期间没有进度提示。用户无法判断自动跳转是否已经安排，也不知道还需等待多久。

## 交互方案

倒计时放在现有成功状态文字中，不增加新的布局元素：

```text
✅ 十字完成！2.5 秒后自动下轮
```

倒计时保留一位小数，每 100 ms 刷新一次。剩余时间不得显示负数，到期前最低显示 `0.0 秒`，到期后立即进入下一轮。

未安排自动下轮时只显示原有成功文字，不显示倒计时。

## 状态设计

倒计时使用独立的响应式展示字段，不直接改写 `statusText`。模板在成功状态文字后拼接该字段，避免倒计时刷新覆盖连接错误或其他业务提示。

组件内部维护：

- 自动下轮截止时间；
- 100 ms 刷新定时器；
- 现有的 2.5 秒跳转定时器；
- 面向模板的倒计时文字。

剩余时间始终按「截止时间减当前时间」计算，而不是每次递减 `0.1`。这样即使浏览器切到后台导致定时器降频，恢复后仍显示正确的剩余时间。

## 调度与清理

提取统一的自动下轮调度与取消方法，供成功结算和复选框变更复用。

### 启动

- 成功瞬间已勾选「自动下轮」：立即从 2.5 秒开始。
- 成功展示期间重新勾选：从完整的 2.5 秒重新开始。
- 重复调度前先清理旧定时器，确保同时最多只有一组倒计时和跳转任务。

### 取消

以下场景同时清理跳转定时器、刷新定时器、截止时间和展示文字：

- 成功展示期间取消勾选「自动下轮」；
- 用户点击新打乱或重置并提前进入下一轮；
- 组件销毁；
- 自动下轮回调开始执行。

蓝牙断开期间沿用当前行为：原有自动下轮任务继续保留。倒计时只在成功阶段显示；状态机离开成功阶段后不覆盖断开提示。

## 错误处理

自动下轮回调异常时，先清理所有倒计时状态，再显示现有错误提示，防止界面继续显示一个已经失效的倒计时。

## 测试

页面回归测试覆盖：

1. 成功且开启自动下轮时，状态文字后出现 `2.5 秒后自动下轮`。
2. 时间推进后，倒计时按截止时间下降并保留一位小数。
3. 取消勾选后，倒计时和自动跳转都被清理。
4. 成功阶段重新勾选后，从完整的 2.5 秒重新计时。
5. 提前重置或开始新一轮时，旧倒计时不再更新，也不会触发重复跳转。
6. 自动下轮回调异常时，只保留错误提示，不显示过期倒计时。
