# 公式训练切层补步可靠性

## 范围

修复 M／S／E 对应实体外层通知缺失、历史逐段补齐、连续训练切题和无序号状态核验的边界；不修改公式或魔方协议，不改版本号，不自动提交或发布。

## 行为约束

- 补步结果即使仍为 pending，也必须先交付其已确认前缀；后续动作继续等待核验。
- 实体动作账本跨普通切题、重试及预打乱切题复用，不能退回过期的会话快照。观察到新 MOVE 序号与账本不一致时，放弃旧基线并请求新状态，不能把上一题动作补进新题。
- 新基线返回前的实时输入仍显示，但本轮不计有效成绩。
- 搜索窗口最多 32 条动作，未知动作最多 2 条；已知动作按其原始序号和时间保留，支持 8 位序号回绕。
- 只合并连续同轴动作的可交换排序，保留每条动作及时间标记，不合并相消路径或不同轴路径。两个同侧未知四分之一转的正反方向仍可能有歧义，继续拒绝猜测。
- 无序号状态需要补步时，先保留候选，再通过不同请求号的第二次状态读取确认；同一请求的重复通知无效。新 MOVE 使候选失效；连续三次独立读取仍不一致则中止，不无限等待。
- 无序号设备推断的未知动作只使用四分之一转，不能把半转误当成一条实际通知。没有真实序号的额外补步不能凭猜测推进序号，后续用第一条新的实时 MOVE 重接计数。
- 补回的动作没有真实时间时，只恢复画面，本轮标记不计成绩，不生成成功记录或有效 TPS。
- 状态读取没有设备请求回显，二次读取只能增强新鲜度判定，不能从根本上证明无线传输绝不丢包。

## 验证

- `npm run test:formula-timer` 包含切层专项回归，覆盖三轴、单／双缺口、长窗口、序号回绕、跨题基线、状态确认及计分保护。
- `scripts/verify-formula-timer-slices.js` 在真实页面验证 6 种键盘切层、M2 缺包恢复、历史前缀交付及无序号旧状态二次确认。
- 保留 BLE、原公式训练、预打乱、实体／屏幕混用和 TypeScript 类型检查。
