# BLE Cross 观察用时记录设计

## 背景

训练记录已经包含 `obs` 字段、观察列和平均观察时间，但结算时仅为手动模式保存观察用时。蓝牙训练同样具有从 `observeStart` 到 `solveStart` 的观察阶段，因此当前记录会丢失已实际产生的观察时间。

## 目标

- 手动或蓝牙训练只要实际经历观察阶段，就保存观察用时。
- 训练记录列表显示已保存的观察用时。
- 平均观察时间只统计具有有效观察用时的记录。
- 兼容现有 `localStorage` 记录，不进行数据迁移。

## 非目标

- 不改变观察计时和还原计时的起止时机。
- 不调整训练记录弹窗布局或其他统计口径。
- 不为未进入还原阶段的轮次虚构观察用时。

## 数据规则

`TrainRecord.obs` 继续使用 `number | null`：

- 当 `observeStart > 0`、`solveStart > 0` 且 `solveStart >= observeStart` 时，保存 `(solveStart - observeStart) / 1000`。
- 其他情况保存 `null`，列表显示 `-`。
- 旧记录中缺少观察时间或值为 `null` 时，继续按无观察时间处理。

观察时间直接取自计时状态，不解析 `observeText`。这样持久化数据不会依赖界面格式。

## 展示与统计

训练记录表沿用现有「观察」列和 `fmtRecSec` 格式化逻辑。有有效值时显示到 0.1 秒，无值时显示 `-`。

「平均观察」沿用现有过滤逻辑，只计算 `obs` 为数字的记录，因此新旧记录可以混合统计。

## 测试

页面回归测试覆盖以下场景：

1. 蓝牙训练具有有效 `observeStart` 和 `solveStart` 时，记录保存观察秒数并可格式化显示。
2. 未经历观察阶段时，记录的 `obs` 保持 `null`，列表显示 `-`。
3. 手动训练原有观察时间记录行为不回退。
4. 平均观察时间忽略无观察时间的历史记录。
