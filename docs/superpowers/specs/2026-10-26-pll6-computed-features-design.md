# PLL 六格实际特征计算与资料核验

## 观察边界

只取当前 3D 魔方 F 面顶层三格（编号 1～3，facelets 18～20）与相邻 R 面顶层三格（编号 4～6，facelets 9～11）。公式库 21 条分别从复原态执行逆公式，再追加无转动、U、U2、U' 四个顶层朝向；不用前 AUF，也不用整体 y 转体。84 个观测与已核对资料的九类 65 行对齐：每行以章节、PLL 名称定位，Z 双眼再按六格色数区分。

## 计算与判定

对六格计算左右三格形态（团、眼、棒左、棒右、灯）、去重色数，以及 15 对格子的同色／对色／邻色关系。对色由当前魔方六面中心的相对面颜色导出，不依赖显示调色板或固定色名。非法面贴纸串与未知状态必须返回无匹配，不能按已有 PLL 名称伪造结论。

由公式库穷举的完整关系签名建立参考目录，去重后可有多种签名归入同一文档行。目录以纯数据存储，运行时从当前 `world.cube.serialize()` 提取实际签名并查得唯一行；只有匹配唯一时才显示准确章节、形态、关键关系与 PLL 名称。原有按案例名称列出候选资料的模式保留作对照，但明确与实际识别区分。

## 资料核验与教学描述

测试从公式库重新穷举 84 个状态，断言签名不跨 PLL 混淆、覆盖 65 行、章节计数与 Markdown 完全对应。将文档明确写出的同色、对色、邻色、六格／子集色数条件转换为可执行断言，逐行核对；文档标记“不考虑”或“未给出”的条件不擅自补全。发现不一致时输出案例、U 朝向、六格原色、条件及实际关系供人工复查，不静默修正资料。

教学描述优先显示形态与足以从同章其他候选中区分该行的少量关系；完整签名留在测试与调试结果，不塞满主界面。资料中一行覆盖多个完整签名并非缺项，不为追求签名数量改写 65 类。

## 验证

纯函数单测涵盖合法／非法输入、关系、形态、色数与实际查询。浏览器自动化从现有公式及 3D 引擎生成 84 个状态、核对目录和文档、验证 UI 随当前屏幕 F/R 六格变化。回归 `npm run test:pll`、`npm run test:ble`、`npm run build`。
