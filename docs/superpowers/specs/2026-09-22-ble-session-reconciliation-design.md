# BLE 会话与轮次对账加固设计

## 目标

修复 BLE Cross 中仍存在的 4 类蓝牙状态问题：

- 轮次同步期间，较旧的 FACELETS 覆盖已经消费的后续 MOVE。
- 快速断开并重连后，新实体状态未强制同步到 3D 画面。
- 旧连接的迟到通知或断开回调污染新连接。
- GAN 批量通知中的历史动作被简单丢弃，导致公式和步数缺步。

修复后，连接会话、协议事件序号、轮次边界和 3D 画面必须遵守同一条单调前进原则：旧会话不能影响新会话，旧序号不能回退新状态，无法立即归属的动作先缓冲再用权威状态对账。

## 方案选择

### 方案 A：继续增加定时器和条件分支

在现有 `bleRoundSyncPending` 和 `bleBaselineHealTimer` 周围增加更多例外判断。改动较小，但状态组合继续增长，无法从结构上阻止旧会话回调和旧基线回退。

### 方案 B：会话令牌、单调基线和轮次缓冲（采用）

为每次连接分配会话令牌；BLE 事件只允许当前会话消费。轮次同步期间暂存 MOVE，FACELETS 到达后按序号和状态决定丢弃、重放或请求新快照。Android GATT 回调只操作产生该回调的实例。

该方案改动覆盖 UI、连接封装、协议适配和 Android 桥，但每层职责清晰，能够一次解决 4 个问题。

### 方案 C：每个 MOVE 后都请求 FACELETS 并全量重绘

实现简单，但 BLE 写请求和整幅重绘过多，会降低动画流畅度，并重新引入画面跳变，不采用。

## 连接会话隔离

`CubeLink` 为每次 `connect()` 创建递增的会话令牌。注册到 `GanCubeLink` 的事件和断开回调捕获本次实例及令牌，只有仍为当前连接时才能更新状态或向上派发。

连接失败或主动断开时：

- 先使当前令牌失效；
- 清除 `gan`、`transport`、设备缓存状态；
- 尝试断开已经创建的传输层连接；
- 旧回调即使迟到，也不能改变新会话状态。

BLE Cross 收到 `connecting` 时清空实体推演态，并标记“等待本会话首个权威状态”。本会话首个合法 FACELETS 必须强制同步 3D 画面，再进入新轮，不受上一会话的 `predicted`、空闲时间或事件序号影响。

## 轮次事件对账

轮次同步开始时记录当前事件序号，并建立临时 MOVE 缓冲。同步窗口内的 MOVE 不立即按 `recovered` 布尔值丢弃，而是记录：

- MOVE 记号；
- 序号；
- 是否由历史恢复产生；
- 到达顺序。

FACELETS 到达时执行以下规则：

1. FACELETS 序号落后于已经消费的实时 MOVE：不得回退 `bleEventSerial`、`predicted` 或 3D；重新请求更新的 FACELETS，并结束旧基线等待。
2. FACELETS 与最后消费的 MOVE 同序号且状态一致：确认当前推演，不重绘、不重复计步。
3. FACELETS 覆盖缓冲动作：使用 `applyFaceletMove`/状态链验证哪些动作已包含在权威状态中；属于按钮点击前的前缀不计步，属于按钮点击后的后缀按顺序走统一动画和计步路径。
4. 无法唯一对账：以最新 FACELETS 对齐 3D，清空歧义缓冲，并请求下一份权威状态，不猜测动作归属。

事件序号只允许单调前进。序号回绕继续使用模 256 比较，但任何基线都不能覆盖已经确认的更新序号。

## GAN 批量动作语义

保留 `recovered` 作为“来源提示”，但不再把它解释成“上一轮动作”。Gen2 单通知携带多步时，除最后一步外都可能为 `recovered=true`，这些动作仍可能属于重置后的快速拨动。

普通训练期间，恢复动作照常消费。轮次同步期间，恢复动作进入缓冲并由 FACELETS 对账决定是否计入本轮。

## Android GATT 生命周期

Android 回调必须校验回调参数 `g` 是否等于当前 `gatt`：

- 旧 GATT 的断开回调只关闭旧实例，不调用操作全局当前连接的 `closeGatt()`。
- 服务发现、描述符写入、特征写入和通知回调若来自旧 GATT，直接忽略。
- 开始新连接前关闭旧实例，但旧实例随后到达的回调不得关闭新实例。

JS 原生传输层的 `services`、`notify`、`disconnected` 事件也只在存在对应连接阶段时消费。连接超时或失败时主动调用桥断开并清理 `connected`、写特征和 pending 状态，避免迟到的 `services` 复活失败连接。

## 3D 权威对齐

所有权威重绘统一经过保留完整视角链的同步函数。普通静止自愈不再只恢复 `z2`，还要保留 `y/y′` 等整体视角，并保持当前计步 history 账本。

本会话首包是例外：它代表新的实体基线，应清除上一会话的层转账本和推演态，再按当前界面视角显示新实体状态。

## 测试要求

自动化回归至少覆盖：

- `MOVE 121`、`MOVE 122` 后收到 `FACELETS 121`，状态不得回退。
- 新连接首包早于 `connected` 回调到达，3D 最终必须与新实体一致。
- 旧会话在新会话连接后触发事件和断开回调，不得改变新会话。
- Gen2 单通知携带多个动作时，轮次缓冲不能静默漏掉首步。
- Android 旧 GATT 断开回调不得关闭新 GATT。
- 序号 255→0 回绕、同序号 MOVE/FACELETS、普通训练补档继续通过。
- `z2`、`y/y′` 后发生权威自愈，视角和公式换名保持一致。

验证命令包括：

```bash
npm run test:ble
npm run verify:blecross
npm run build
```

Android 桥修改还需运行项目现有 Gradle 编译任务，并确认 APK 侧 Java 编译通过。

## 非目标

- 不更改 BLE Cross 界面布局和交互文案。
- 不增加新的魔方品牌或协议。
- 不重写 Three.js 魔方引擎。
- 不改变手动模式的打乱、计时和公式预览语义。
