# 公式计时蓝牙转动补步设计

日期：2026-11-01

## 问题与目标

实体快速操作 S、M 等动作时，设备通常上报两个普通面转动。若其中一个实时通知漏掉，公式计时页面只画出另一个面。当前 GAN 协议遇序号断档会请求完整状态，但公式计时忽略状态帧和 `recovered` 历史事件，因而无法纠偏。另一个容易遗漏的场景是最后一步通知丢失：没有后续 MOVE，就没有序号断档可供检测。

目标是正常通知仍即时播放；在本轮内找回可确定的缺失转动，并让画面、完成判定和成绩使用同一份完整动作账本。不允许静默丢步或根据不可靠猜测判成功。实体魔方不必与屏幕打乱状态一致。

## 方案选择

1. **只接受历史 `recovered` MOVE：** 改动少，但现有 GAN 驱动在断档时会跳过缺失序号，不能保证发出历史事件；最后一步丢失也无法仅靠 MOVE 发现。
2. **直接用 FACELETS 覆盖画面：** 能对齐实体，但实体与题面无需同步，会把随机题面覆盖为另一状态，不能采用。
3. **本轮实体状态账本 + 有界补步（采用）：** 保留实体的独立基线，记录每次已收到的 MOVE；对比后续权威状态推断缺失的普通面动作，仅在结果唯一且序号、轮次一致时补回；不确定时停止本轮并提示重新尝试。正常路径不等待补步。

## 数据流和边界

- 连接及每轮开始时保留实体 FACELETS 基线及其序号。实体状态只用于校验相邻时间段的动作差异，不直接作为 3D 魔方的题面。没有有效基线时可以实时跟随，但若出现断档则不能凭空补步，应暂停并提示重新获取基线。
- 对每个实时 MOVE 维护原始序号、动作和当前轮次。连续序号按现有路径立即映射、动画、计时；缺序号时记录缺口并请求权威状态，暂存新动作，待补步确认后按序应用。历史 MOVE 只允许填当前轮次的明确缺口，不能重放已用序号，也不能流入新题。
- 用已有普通面转动状态计算能力验证候选补步：必须与权威 FACELETS 完全一致。优先用已收到的动作和序号限制候选；若存在多个不同的合理动作序列、缺口超出有界搜索范围，或状态已过期，不选择第一个搜索结果冒充真相。
- 即使没有发现序号断档，最后一次转动后也需进行一次节流的状态核验，以发现末步丢通知。状态未核验前，2 秒停转失败不能抢先结算。中间补步而后续实时动作已收到时，以后续实时动作的时间结算；完全丢失末步时，无法知道其实际发生时间，只补齐画面，本轮不计有效速度成绩，并提示「末步已补回，时间无法精确核验，请重试同题」。核验超时或失败时暂停并显示无法核验，不给出成功成绩。
- 逻辑画面是判定源。补步加入同一逻辑动作账本后再判定成功；动画可追上逻辑状态。若画面已经显示了缺口后的动作而需要插入前置补步，则应从本轮题面按序重放，不能把补步直接追加在末尾造成顺序错误。
- 切题、重试、重连、切换页面时清理当前轮次的补步请求和缓存；异步返回须带轮次标识检查。保留原有无需实体与题面同步、F2L／OLL／PLL 完成条件、临时重点训练及记录格式。

## 验证

- 连续 `F'`、`B` 两步保持实时跟随；缺中间一步、历史事件迟到、重复帧、8 位序号回绕、缺最后一步等场景得到正确且不重复的屏幕动作。
- 实体基线与随机题面不同、带 z2 的题、跨轮迟到状态帧、重连后序号重置，都不能让实体状态覆盖题面或污染新题。
- 同一权威终态能由多个候选解释或状态请求超时时，页面明确暂停并提示，不误判成功／停转失败；末步补回的画面正确且成绩无效，其他可计时的恢复不含核验等待。
- `npm run test:formula-timer`、`npm run test:ble`、`npm run build` 和手机端真实蓝牙快速 S／M 操作回归。
