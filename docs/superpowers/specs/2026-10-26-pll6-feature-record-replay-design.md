# PLL 六格特征提示、成绩筛选与案例复盘设计

## 目标与边界

在现有 `?mode=pll6` 页面增加“显示当前特征”复选框、完整的判断及蓝牙成绩记录、筛选和屏幕案例复盘。复盘仅恢复**当时屏幕 3D 魔方的起始状态**，不恢复、不推断当时实体蓝牙魔方的状态。九类特征的程序自动验证仍是后续独立阶段，本次不实现。

## 特征提示

- 在 21 个 PLL 名称按钮上方放置“显示当前特征”复选框，默认关闭，选择保存在本机存储。开启后内联显示本题对应的九类资料行；关闭后不占提示区域，也不遮挡 3D 魔方。
- 资料直接来自用户已核对的 `docs/pll-six-sticker-observation.md`。同名 PLL 可能在多个观察朝向有多行，标题明确写“本题候选特征”，展示章节、形态、同色／对色／邻色关系和色数。切换、重试及复盘案例时同步更新。
- 提示只是按已知案例名称从文档取候选行，**不宣称识别当前屏幕六格的精确观察朝向**；不改变判断正确性。

## 记录和计时

- 每一次点击 PLL 名称按钮单独记一条：选择正确标“判断正确”，选择错误标“判断错误”并留在当前题继续选择。每条保存时间戳、正确 PLL、所选 PLL、从案例显示到本次点击的累计“判断时间”，以及当时屏幕案例的精确打乱公式。后续点击继续从最初显示案例计时，不因错误点击重置。
- 蓝牙首次有效 MOVE 到六面还原另记“蓝牙还原”成绩，时间标“公式拧动速度”。该记录同样保存屏幕案例的精确打乱公式；实体与屏幕无需同步。恢复的旧通知、迟到旧帧不产生额外成绩。
- 记录继续使用本地存储 `pll6Records` 并保持最多 200 条。新结构带版本或可选字段；旧记录仍能显示，若缺少案例打乱信息则明确不能复盘，不伪造一个新案例。
- 新案例、Esc／清除重试按现有训练规则处理。复盘时暂停本题计时并忽略蓝牙训练事件，关闭复盘后恢复之前的当前题且重新开始本题计时；复盘本身不生成记录。

## UI 与复盘

- 记录区域提供一个统一列表和两个筛选器：结果类型（全部／判断正确／判断错误／蓝牙还原）、PLL 名称（全部／21 种）。行内显示时间、正确名称、判断时所选名称、对应时间指标和“复盘”按钮。
- 复盘按钮将已有 `world.cube.twister.setup(record.scramble)` 应用到画面，不产生新随机案例；提示区可显示该记录的正确 PLL、误选答案和候选特征。
- 复盘期间明确显示“正在复盘”和“返回训练”按钮；返回时恢复此前的训练案例画面并重置计时，不改变历史成绩。若旧记录无 `scramble`，按钮禁用并提示原因。
- 大量错误点击仍只保留最近 200 条；列表按原有倒序排列，筛选在内存中进行，不更改持久化数据。

## 验证

单测覆盖错误与正确点击分别记账、累计判断时间、蓝牙拧动速度、每种记录的案例公式、旧记录兼容和复盘不产生记录。浏览器验证复选框显示／持久化、两维筛选、复盘恢复精确状态、返回训练与移动端不遮挡魔方；执行原有 PLL 和蓝牙回归测试与生产构建。
