# CFOP Cross＋F2L 三维播放与蓝牙跟练设计

## 目标与范围

把 `/dd/workspace_rust/cube_cross_solve/cfop.html` 的首阶段 Cross／XCross／XXCross／XXXCross／READY、逐组候选和一键逐槽位 F2L 求解接入 Cuber。结果必须能在 Cuber 的 3D 魔方上逐步播放，并按「十字／第几组 F2L／槽位」分行显示公式。蓝牙实体魔方跟练时，由实际转动推进步骤；转错立即暂停并提示纠错。

本期只学习至四组 F2L 完成，不包含 OLL／PLL，不新增训练记录或改变 BLECross 的计时、判定和自动下轮。求解器保持 Rust 算法与返回语义，一键逐槽位解法不声明全程最短；人工逐组的候选排序和动作限制沿用 Rust 页面。打包发布不属于本功能开发范围。

## 接入形式与界面

比较三种形式：独立 `?mode=cfop` 页面、嵌入 CrossF2L 训练页、直接嵌入 Rust HTML。选择独立页面：复用现有 AppShell 导航、全局蓝牙会话和 Cuber `World`／`twister`，隔离 CFOP 的搜索、播放和实体跟练状态；不引入 Rust 页自身的 CSS 3D 魔方，也不改其他模式的训练状态。

页面上部提供输入打乱公式／54 位 URFDLB 状态、读取当前实体状态、首阶段选择、逐组或一键求解，以及搜索进度／取消。候选选中后固定一条完整学习路线；手机端 3D 魔方始终留在可见区域，下部为可滚动的阶段公式与播放控件。路线示例：

```text
十字                     R U R' …
第 1 组 F2L · FR          U' R U R'
第 2 组 F2L · BL          y U' L' U L
第 3 组 F2L · FL          …
第 4 组 F2L · BR          …
```

每行保留完整公式和单步高亮，点击行跳至该阶段起点；窄屏时标签和公式可以各占一行，公式横向换行，不拆成竖排单字。首阶段同时完成的 F2L 槽位显示独立的「第 N 组 · 槽位（首阶段已完成）」零动作行，关联首阶段末状态，不重复分配十字动作；一段同时完成多槽时标注「同时完成」并共用动作范围。`y/y'` 等视角步骤保留在所属阶段公式中，但不计入面转步数。提供返回起点、上一步、下一步、播放／暂停和速度；跳步或返回先结束当前动画，再把独立 3D 魔方恢复至所选帧。

## 求解、分段与播放数据流

复用项目已同步的 `public/cube_cross_solve.js` 和同版本 WASM 的 `cfop_start_js`、`cfop_stages_js`、`cfop_auto_f2l_js`、`cfop_verify_js`。新增 CFOP 专属搜索 Worker／客户端，按需加载十字表与联合表；采用请求 ID、取消和超时，取消时终止计算 Worker，过期结果不落页面。状态帧生成放在另一轻量 Worker，避免长搜索阻塞播放。静态表缺失或 WASM 版本不匹配要显示明确错误或受控回退，不在 UI 主线程重算昂贵搜索。

模型分成 `inputSnapshot`、`selectedStages`、`segments` 和 `frames[0..N]`：每个动作有原始记号、所属阶段和期望结束状态；每个状态帧有 54 位面贴纸、Cross 是否完成和已完成槽位。使用 Rust 候选 `segments` 的动作边界、`completed_slots`／`restored_slots`，并用逐动作 `cfop_verify_js` 核对分段后的状态，不根据公式字符串猜测槽位。帧数必须等于动作数加一；结果缺字段、状态不合法、未识别记号或与 Cuber 3D 重放状态不一致时拒绝播放并提示，不静默跳步。

3D 播放只作用于本页独立 `World`。动作动画走现有 `twister.push`；定位到任意帧可从起点重建该前缀，但必须验证 Cuber 动作记号与 Rust 的 `y/y'`、切片等记号在同一坐标定义下等价。`twister.setup` 会重置魔方和历史，不能拿它在共享训练魔方上跳帧。颜色／坐标始终由输入快照和选中路线确定，不因相机拖动重算求解。

## 蓝牙实体跟练

沿用 AppShell 的全局 CubeSession 和各页面「跟随实体魔方」开关。CFOP 增加受控的实体快照入口，明确区分进入页面前的历史状态、进入后新转动与本轮主动读取的起点；现有普通页面仅获派发新 MOVE，不能误把旧 `facelets` 当作本轮确认。开始跟练前，所选路线起点必须与实体完整状态经统一坐标映射后相等；否则提示读取实体状态重新求解或把实体魔方恢复到路线起点，禁止直接推进。

跟练模式不自动推进 3D。每条新实体转动先更新实体状态和 3D 的实际状态，再与期望时间线核对：匹配则推进光标；不匹配则立即暂停，显示预期与实际动作并保留真实状态。暂停后用户可转回上一个已确认状态继续；若实体已偏离路线而不想撤销，可从当前实体状态重新求解，原路线不悄悄改写。序号／请求代号用于去重和丢弃迟到事件；收到断连、缺帧或无法一致校验的状态时暂停并要求重新同步，不凭旧通知猜测完成。

`y/y'` 是持方朝向变更：3D 自动播放执行相应旋转，蓝牙跟练则停在该动作，由用户手动确认朝向后继续，并将后续实体六面记号映射到新坐标；单纯拖动相机不算确认。若结果含设备无法报告的 `S` 等切片，3D 播放仍可使用；跟练只有在设备快照能验证完成后才允许手动确认，否则把该候选标为「仅 3D 播放」，给出重新选择蓝牙兼容候选的入口。不能只按一次确认就假定实体已经执行了切片。

自动播放和实体跟练互斥；切换路线、输入、首阶段或离开页面时停止动画和旧搜索，取消当前跟练，防止旧动作推进新路线。页面的跟随开关关闭时不消耗实体 MOVE，当前路线和 3D 状态保留。

## 错误处理与验收

搜索超时、取消、资源缺失、无解、无可跟练候选分别显示可重试的状态，不冻结 3D 操作。输入或候选变更后异步返回的旧结果不得覆盖新路线。手机端点击公式或播放按钮不能意外触发相机旋转或求解重算。

1. 对 Rust 页面提供的相同输入，首阶段、逐组与一键模式的候选动作、完成槽位、最终 Cross／F2L 状态一致；已完成槽位与同时完成槽位标注正确。
2. 3D 从帧 0 逐步、整段、暂停、后退、跳阶段、返回起点后与验证帧一致；`y/y'`、切片记号不丢失，公式每阶段单独换行且当前动作可辨认。
3. 蓝牙起点不一致不能开始；正确动作推进，错误动作立刻暂停且保留实体实际状态，转回后可继续，从当前状态重算不混入旧路线；断线、重复和迟到事件不误推进。
4. 手动确认视角后后续动作坐标正确；切片无法验证时不假装支持实体跟练。关闭跟随、切页和搜索取消不影响 BLECross／CrossF2L 现有状态；生产构建包含同版本 WASM、Worker 与所需表文件。
