# BLE Cross 蓝牙实时步骤固定视角设计

## 背景

蓝牙魔方的 MOVE 事件使用物理核心帧记号。当前 3D 镜像动画在事件到达时调用 `displayMove(move)`，按事件当时的视角换名；实时步骤文本和完成后的用户解法则保存物理记号，并在每次渲染时调用 `displayFormula()`，按最新视角重新换名。

因此同一批历史步骤会在用户按 z2、y 或 y′ 后被重新解释。例如已显示的 `D R` 在 z2 后会变成 `U L`，但当时的 3D 动画已经按原来的 `D R` 播放，造成文字历史与动画不一致。

## 目标

- 蓝牙 MOVE 到达时固定该步的屏幕记号，后续视角切换不改写历史步骤。
- z2、y、y′ 后的新 MOVE 按新视角显示。
- 3D 镜像动画、实时步骤文本和完成后的用户解法使用同一转换结果。
- 物理状态推演、判定、求解和 HTM 步数继续使用原始物理记号。
- 单步和整段公式复用同一个换面函数，消除重复映射实现。

## 非目标

- 不改变 GAN Gen2/Gen3/Gen4 的 MOVE 解析与方向定义。
- 不改变 Cross/XCross 判定、最优解求解或槽位映射。
- 不把视角切换操作 z2、y、y′ 本身计入用户解法或步数。
- 不改变手动练习的 history 记号语义。

## 统一转换接口

在 BLE Cross 组件内保留一个记号转换源：

```ts
private displayMoveWithOps(move: string, ops: BaseOp[]): string
```

该函数将物理核心帧单步记号转换为指定视角下的屏幕记号，并保留 `'`、`2` 等后缀。

现有入口改为薄封装：

- `displayMove(move)` 使用实时 `effectiveViewOps()`。
- `displayFormulaWithOps(formula, ops)` 拆分公式后逐项调用 `displayMoveWithOps()`。
- `displayFormula(formula)` 继续使用实时视角，但内部复用上述函数。

这样最优解、打乱公式、槽位展示等现有调用点仍可选择实时视角或既有 `bestViewOps` 快照，同时不再重复实现首字母映射。

## 蓝牙步骤记录

新增只服务于蓝牙用户步骤展示的记录结构：

```ts
interface DisplayMoveRecord {
  physical: string;
  display: string;
  viewSig: string;
}
```

每个有效 MOVE 在 `onMoveEvent()` 的 solving 分支中：

1. 复制当前 `effectiveViewOps()`。
2. 用统一转换函数得到屏幕记号。
3. 将物理记号、屏幕记号和视角签名一起追加到显示记录。
4. 3D 镜像动画直接使用该次转换结果，确保动画与文字同源。
5. 原有 `userMoves` 仍只追加物理记号，用于状态推演、判定和 HTM 计数。

尚未进入 solving 的打乱匹配步骤不加入用户解法，但 3D 镜像仍用同一统一转换函数。

## 分段化简

GAN 可能把一次 180° 转动上报为同面的两个 90° MOVE，因此显示历史仍需化简。化简按连续且 `viewSig` 相同的片段执行：

- 同一视角内 `D D` 显示为 `D2`。
- 同一视角内 `D D'` 相消。
- 跨视角边界绝不合并。
- 示例：物理步骤 `D`、按 z2、物理步骤 `D` 显示为 `D U`，而不是 `D2`、`U2` 或把第一步重写为 `U`。

每段使用现有 `simplifyMoves()` 处理该段已经转换完成的屏幕记号，然后按时间顺序拼接所有段。

## 展示与生命周期

- `liveStepsText`：蓝牙模式读取固定显示记录的分段化简结果；手动模式保持现状。
- `userSolutionText`：蓝牙完成态读取同一结果；不再用完成时的最终视角重新转换物理公式。
- `finishSuccess()`：蓝牙的 `userSolution` 继续保存化简后的物理公式，供内部记录和兼容逻辑使用；显示改读固定显示记录。
- `startSolving()`、`resetRound()`、`newScramble()`、断连回落和所有清空 `userMoves` 的生命周期入口必须同步清空显示记录，禁止跨轮残留。

## 防御行为

- 非法或空 MOVE 不加入显示记录，沿用现有事件校验结果。
- 视角链为空时转换恒等。
- 视角签名使用规范化后的 `effectiveViewOps()` 序列化结果，等价视角得到相同签名。
- 转换只影响显示数据，不回写 `predicted`、`userMoves` 或求解输入。

## 测试

扩展 BLE Cross 浏览器回归，覆盖：

1. 标准视角收到 `D R`，实时步骤显示 `D R`。
2. 随后按 z2，已有文本仍为 `D R`。
3. z2 后再收到物理 `D R`，追加显示为 `U L`，完整历史为 `D R U L`。
4. z2 前同视角连续两个 `D` 化简为 `D2`；跨 z2 的两个物理 `D` 显示为 `D U`，不跨段合并。
5. y/y′ 与 z2 混合视角下，每个新步骤的文字等于同一事件交给 3D 镜像的记号。
6. 完成态 `userSolutionText` 与最后一次实时步骤文本一致，之后再切视角也不变化。
7. 重置和新一轮后显示记录为空。
8. 既有模式切换、公式预览、蓝牙多轮重置和协议测试继续通过。

## 验收标准

- 已出现的蓝牙步骤文本不因后续 z2、y、y′ 改变。
- 新步骤始终对应事件发生时的当前 3D 屏幕视角。
- 文字与 3D 镜像动画使用同一个转换结果。
- 同视角 HTM 显示化简正确，跨视角不错误合并。
- 手动练习和物理判定逻辑无行为变化。
