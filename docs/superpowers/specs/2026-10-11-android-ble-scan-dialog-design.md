# Android 蓝牙扫描弹窗与诊断日志设计

## 问题

Android App 点击“连接魔方”后会执行 `openScanDialog()` 并启动原生 BLE 扫描，但页面模板没有渲染 `scanDialog`、`scanDevices` 和 `pickDevice()` 对应的界面。因此即使后台扫描成功，用户也看不到设备列表，表现为按钮没有任何反应。

扫描阶段的原生错误目前只进入 JavaScript 控制台；原生层除停止扫描异常外也缺少关键阶段日志，导致权限、扫描和 GATT 连接问题难以从 Logcat 定位。

## 方案比较

### 方案 A：补齐应用内扫描弹窗（采用）

在现有 BLE Cross 页面增加 Vuetify 对话框，直接复用已有 `scanDialog`、`scanStatus`、`scanDevices` 和 `pickDevice()` 状态。原生错误通过传输层回调显示在弹窗中，同时增加 Java Logcat 日志。

优点是用户能在 App 内完成扫描、选择和连接，改动与现有架构一致；缺点是需要同时修改模板、TypeScript 传输层和 Java 桥。

### 方案 B：只自动连接第一个 GAN 设备

扫描到第一个疑似 GAN 设备后立即连接。实现较少，但附近有多个魔方时无法选择，也容易误连，因此不采用。

### 方案 C：只增加日志，不补界面

可以帮助开发者排查，但普通用户仍无法选择扫描到的设备，不解决核心问题，因此不采用。

## 界面行为

- 点击“连接魔方”立即打开扫描对话框。
- 对话框顶部显示“扫描蓝牙魔方”。
- 扫描中显示进度和提示文字。
- 每个设备显示名称和 MAC 地址；点击一项后关闭弹窗并连接该地址。
- 提供“重新扫描”和“取消”按钮。
- 取消或关闭弹窗时调用 `stopScan()`，避免扫描继续占用系统资源。
- 15 秒内没有设备时显示明确的未发现提示。
- 权限拒绝、蓝牙未开启、扫描不可用等错误直接显示在对话框内，而不只是写控制台。

## 传输层错误通道

`NativeBridgeTransport` 增加扫描错误监听：

- `onError(callback)` 注册错误回调。
- 收到 Java `error` 事件且当前没有正在等待的 GATT 连接时，将消息传给扫描界面。
- 若正在连接设备，继续按现有逻辑 reject 连接 Promise，避免改变连接错误语义。
- `bluetoothOn` 事件提示用户重新扫描，不自动执行未确认的连接。

## 原生日志

`BleBridge` 使用 `BleBridge` tag 输出以下阶段：

- JavaScript 请求扫描。
- 当前 Android 版本与缺失权限。
- 权限申请结果。
- 蓝牙未开启或扫描器不可用。
- 扫描开始、停止和发现设备。
- 请求连接的地址。
- GATT 连接状态、服务发现状态和服务数量。
- 通知订阅、写入失败及断开。

日志不记录协议明文密钥；MAC 地址作为用户正在调试的设备标识保留在 debug 日志中。

## 测试与验收

- 先添加静态回归测试，确认模板包含扫描对话框、设备列表、重试/取消操作。
- BLE 单元测试增加原生传输层扫描错误回调测试。
- Java 编译验证新增日志不会破坏 Android 构建。
- 运行 `npm run test:android`、`npm run test:ble` 和完整 `android/build-apk.sh`。
- 检查 APK 包含更新后的前端资源。
- 真机验收：点击按钮可见弹窗；首次触发权限请求；扫描到设备后可选中并连接；拒绝权限时弹窗显示错误；Logcat 可看到完整阶段日志。
